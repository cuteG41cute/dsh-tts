## 二、逐项说明「哪些内容被读、哪些没被读」

### ✅ 会读出来的

| 内容 | 读出来的样子 |
|---|---|
| 普通段落 | 原文照读 |
| **加粗** | 只读文字，不带强调（TTS 无重音标记） |
| 表格 | 表头和每行单元格的文字**连成一串顺读**，没有「表格」「第几列」提示（见上面第 1 块的「位置、功能。……」） |
| 列表 | 各项连读，序号不读（「第一」「第二」是我原文里写死的才会读） |
| 标题（## 完成了什么…） | 只读标题文字本身 |
| emoji | ⚠️ 交给 TTS 引擎处理；多数中文音色会跳过或读不出 |
| 链接文字 | 只读可见文字，不读 URL（URL 若是裸文本则会逐字念，见下） |

### ❌ 不会读出来的（当前提取规则刻意剔除）

| 内容 | 原因 |
|---|---|
| 代码块（``` 包裹的整段） | 提取时移除 `pre`——整块跳过 |
| 行内代码（如 `POST /dsh-tts/api`、`cordis.patch.yml`、`~/.dsh/profiles/...`、`node --check`） | 提取时移除所有 `code` 元素——**这些词在朗读里直接消失**。上面的模拟文本里你看到的「接入 cordis.patch.yml」「宿主转发到自动补路径」就是行内代码被抠掉后造成的断句残留 |
| 徽章/按钮类 UI 元素 | 不存在于正文 DOM |

### ⚠️ 会被读、但效果一般的内容

| 内容 | 效果 |
|---|---|
| 裸 URL（https://api.example.com/v1） | TTS 会逐字符念「h t t p s 冒号 斜杠 斜杠…」，很难听 |
| 表格 | 连读后逻辑不清晰，信息密的大表格基本听不懂 |
| 「〜/.dsh/...」这类路径残留 | 路径的行内代码部分被删后，剩下的「源码在工作区 dsh-tts，」反而通顺；但没删干净时会出现「～斜杠」这类碎片 |
| 「⚠️」「✅」 | 依音色而定，多半静音跳过 |

## 三、模拟暴露出的一个真问题 + 修法

**问题**：当前规则把**行内代码**也删了，这太狠——「重启后点头部『朗读』芯片，填你的接口地址」这类句子里，关键名词（接口地址、模型名、文件名）经常就在行内代码里，删掉后句子残缺（上面模拟第 1 块里「宿主转发到自动补路径，填就 曰v1 就行」这句的破碎感就是它造成的）。

**建议修法**（一行改动）：
- `pre`（整块代码）→ 照旧删除；
- `code` → **只删「在 pre 里面的」**，独立的行内代码**保留文字**参与朗读。

修完后的同一句会读成：「宿主转发到 P O S T 斜杠 dsh 短横 t t s 斜杠 a p i（路径类仍难听），但「已接入 cordis.patch.yml」「运行 node 短横 check 通过」这类就是通顺的了。」

路径/命令类行内代码仍会逐字符念，这是 TTS 的天然短板；如果嫌吵，可以再进一步把「看起来像路径/URL 的行内代码」替换成一句「（此处有路径）」或直接跳过，做成设置面板里的一个「跳读代码」开关。
